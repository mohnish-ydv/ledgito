# Ledgerly 1.0.1 — UX Stability Release

This release addresses the complete first-device QA report against Ledgerly 1.0 Final.

## Root causes fixed

### Lists looked empty even though data was saved

Room and ViewModel flows were working, but every affected `RecyclerView` lacked a layout manager. Android therefore skipped child layout and showed no rows. Explicit `LinearLayoutManager` declarations were added to:

- Activity
- Accounts
- Categories
- Budgets
- Recurring
- Calendar
- Dashboard recent activity
- More advanced tools
- Workspace tools
- Split editor

### Home could not be recovered from another bottom tab

The standard state-restoring bottom-navigation wiring was replaced with a single predictable root stack. Selecting Home always pops back to the dashboard; selecting another root first returns to Home and then opens the chosen tab.

### Controls were under system bars

Target SDK 35 enforces edge-to-edge on Android 15. Both activities now apply status-bar, display-cutout and gesture/navigation-bar insets while retaining their original design padding.

### Dashboard ring and Quick Add placement

The cash-flow ring now draws inside a centred square and the hero card has enough measured height. Quick Add is centred within the bottom dock rather than sitting too far above it.

### Onboarding clarity

The first page is now a single calm welcome moment, using the supplied reference screenshots only as design inspiration. Account setup remains on later steps. The opening-balance date is selected through a calendar and cannot be typed manually.

## Compatibility

- package: `com.mohnishraj.goldmineledger`
- Room database: version 3, unchanged
- migrations: 1→2 and 2→3, unchanged
- no destructive migration
- no INTERNET permission
- existing Ledgerly 1.0 data is preserved
